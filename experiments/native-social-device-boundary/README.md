# Synthetic signed-device boundary probe

This is a disposable host with one `LiveProcess`-style classic extension. It tests whether the extension can read a synthetic host-only Application Support file, a Keychain item in the app-ID group shared by the two processes, and a second item in an explicitly requested host-only Keychain access group. It does not contain or inspect CalcVault vault data, social credentials, a TikTok IPA, or a guest binary.

The host's base bundle ID is `com.jaylintaylor.calcvault` so SideStore can attempt to replace the existing CalcVault install instead of consuming another active-app slot. The extension has its own bundle ID inside the IPA. SideStore's **Keep All Extensions (Use Main Profile)** mode may sign both with one registered App ID; this must be verified on the owner's device. Reusing the profile is a signing experiment, not a confidentiality claim.

The extension is invoked using the same nonpublic `NSExtension` class and `com.apple.ar.viewer` extension point used by the pinned LiveContainer 3.8.0 research path. This probe is not production code. Passing it would be a necessary baseline, not proof that a native TikTok guest is isolated after LiveContainer's loader and hooks run.

The first signed-iPhone probe found that the extension read the default-group Keychain fixture. This follow-up tests a narrow hypothesis: SideStore may preserve a host-only `keychain-access-groups` entitlement while leaving it off the extension, even when both use the main provisioning profile. The IPA is ad-hoc signed with a **fake** team-prefix entitlement solely so SideStore's resigner can inspect and replace it; the ad-hoc signature is not an install credential. The probe derives the signing-team prefix from a disposable default-group item, then explicitly creates the host-only-group item; it does not require that group to be the default. It does not display or log the owner's actual team/group identifier. If SideStore strips or rejects the entitlement, the host reports an inconclusive test rather than weakening the check.

## Evidence gates

1. Manual CI builds the separate simulator host and `iphoneos` host plus embedded extension, ad-hoc signs the iPhone bundle with a fake host-only-group entitlement for SideStore to replace, smoke-tests that a separate simulator extension process returns a result item, and uploads a resignable IPA with SHA-256. Ad-hoc simulator signing may lack usable Keychain entitlements; those checks are explicitly **NOT TESTED** when host fixtures cannot be created. A simulator read is **not** an isolation pass.
2. Before phone installation, verify the IPA's base bundle ID and embedded extension, download/hash, and preserve any CalcVault data or sessions the owner wants. The probe does not export or recover them.
3. In SideStore, select **Keep All Extensions (Use Main Profile)**. Stop if it proposes another App ID, another active app, removal of Spotify, or deletion of CalcVault. Do not use an extension-stripping option: that makes the test inconclusive.
4. Open **CalcVault Boundary Probe**. It runs once automatically; **Run test again** retries. A result must show distinct host and extension PIDs, the file result, and separate shared-app-ID/host-only Keychain results. A screenshot of this synthetic-only screen is sufficient for the next device observation.
5. On the signed phone, host-only-group fixture creation and host readback must succeed first. `READABLE` for the host-only Keychain item fails the new boundary. `NOT READABLE` is only a provisional pass for that one item if the host created/read it and the extension ran separately. Missing group, fixture, extension, report, or timeout is inconclusive. The shared app-ID control may be `READABLE` or `NOT TESTED` if that group was not granted to the host; neither determines the host-only result. Production would need every sensitive Keychain item moved to an actually host-only group. Never infer real vault safety from this baseline alone.

The probe creates only a uniquely named synthetic file and two Keychain items under the exact test service `org.example.calcvault.synthetic-boundary-probe`. It removes those fixtures after a result or timeout. It does not enumerate, rewrite, or delete other app data. An interrupted run may leave a synthetic item; the next run replaces only the exact test accounts in their respective groups.

Because this build uses CalcVault's base ID, installing it can replace the existing app and may affect local settings and browser sessions. It must not be installed until the owner reviews the artifact and accepts that tradeoff. Restore the ordinary CalcVault build through an in-place SideStore install with the same signed identity; do not delete the app as a troubleshooting shortcut.
