# CalcVault certificate omission research

This patch targets SideStore source revision `6032424a0e56c1c319762e786099bdd9186a238b`, the build reported on the owner's phone. The changed source file is byte-identical to revision `0dd743f75afc358b0ba4a002feb5f19474492371`. It changes only `EmbedSigningCertOperation`. When SideStore's recorded original app ID or the staged bundle ID is `com.jaylintaylor.calcvault` or has that ID plus a dot suffix, the operation removes any old `ALTCertificate.p12` or `ALTCertificate.der` from the staged copy and omits the new embedded certificate. This covers a re-sign after SideStore assigned a custom ID that no longer resembles CalcVault's original ID. SideStore's temporary `SideBackup-...` helper is excluded even though that helper is given the target app's ID. Other apps retain SideStore's original behavior. The staged copy is prepared before signing; the installed source app and its data are not edited by this operation.

The policy checks both IDs because SideStore's re-sign pipeline can stage an already rewritten ID, including an arbitrary custom ID. It excludes the backup helper by its dedicated staging-directory prefix, as observed in `StageBackupAppOperation`. It does not remove certificates from SideStore itself or from other installed apps. SideStore's reviewed refresh pipeline installs renewed provisioning profiles without running `EmbedSigningCertOperation`, but an in-place install, refresh, and signed-device retest are still required before claiming compatibility.

The manual CI workflow applies the patch to a fresh pinned checkout and builds an unsigned/ad-hoc SideStore IPA using public source and placeholder signing settings. Its visible version marker is `0.7.0-20260911.328+6032424a.cv1`. It receives no Apple account, personal certificate, pairing file, or signed IPA. A passing build proves only compilation and packaging, not certificate omission during a real SideStore install. [Run 36309985963](https://github.com/Jaytay04/CalcVault/actions/runs/36309985963) produced the final research IPA; its SHA-256 is `d6b7bf4f9c8017297b125d1df451fca8ac93050f7d4fa5da08bd72e6e818d039`.

## Controlled phone test

The research IPA has the same main and widget bundle IDs and the same archive entry-name set as the stock SideStore 0.7.0-alpha IPA. SideStore's [FAQ](https://docs.sidestore.io/docs/faq) allows testing a version by sideloading it through SideStore or iloader without removing the original, but explicitly does not guarantee data retention for unofficial builds. Keep a copy of the stock IPA and a working iloader/pairing recovery route. Never upload a pairing file, Apple credentials, signed IPA, or signing certificate to this repository or the CI workflow.

Install the research IPA **in place** through the working SideStore; do not delete SideStore, Spotify, or CalcVault. First confirm SideStore reopens, shows the `.cv1` version marker, and still lists the existing apps. If that fails, stop and use the stock SideStore IPA/recovery route. Do not infer a fourth Home Screen app or App ID from the public archive alone; check the actual signed installation.

Only after SideStore itself passes, reinstall the same Build 14 synthetic CalcVault IPA in place through the patched SideStore. A normal profile-only refresh does not remove a certificate already embedded in the installed app. The synthetic host report should show P12=absent and DER=absent. With both independent Keychain fixtures READY and the guest launched, every stage should show `signing-export open ABSENT`, host-only file/Keychain DENIED, and host sentinel UNCHANGED. If the report is inconclusive or still says OPENABLE, do not import real TikTok. Check a subsequent SideStore refresh and app relaunch before considering this signer compatible.

The probe does not inspect certificate contents. Even if the signing-export result passes, the guest can read the shared app-ID Keychain group. Current CalcVault credential queries use that default group; migrating them into the verified host-only group without data loss remains a separate gate before native TikTok. Guest lifecycle and actual TikTok compatibility also remain untested.
